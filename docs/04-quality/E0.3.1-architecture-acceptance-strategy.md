# E0.3.1 Architecture Acceptance Strategy

**Status:** Proposed acceptance plan  
**Implementation Status:** Not Implemented  
**Verification Status:** Not Verified  
**Related:** ADR-017–020

## 1. Purpose

Define evidence required to close E0.3.1 architecture review and to gate E1 implementation. This document describes test obligations; it does not claim that tests or software already exist.

## 2. Architecture acceptance matrix

| Area | Required evidence | Failure condition |
|---|---|---|
| Domain ownership | Architecture test rejects foreign private repository/table access | A domain mutates another domain's authoritative records |
| Coordination | Cross-domain use-case tests exercise published contracts only | UI or coordinator bypasses owning domain |
| Rust dependency graph | Cargo build plus forbidden-dependency checks | Domain imports Tauri, SQL, OS or provider SDK |
| Workspace isolation | Negative tests for queries, search, jobs, files, imports/exports and operation lookup | Any cross-workspace disclosure or mutation |
| Transaction/Outbox | Commit/rollback and crash-window tests | State commits without required Outbox or vice versa |
| Idempotency | Duplicate delivery and same-key/different-payload tests | Duplicate side effect or silent key reuse |
| Operation recovery | Restart, timeout-after-submit and reconciliation tests | Indeterminate outcome blindly resubmitted |
| Authorization | Expired/revoked grant and changed approval digest tests | Existing Operation bypasses current policy |
| Event compatibility | Old/new fixture, unknown type/version and quarantine tests | Unsupported schema interpreted as known |
| Backup/restore | Restore with operation metadata, attachments and manifest validation | Restored data silently loses required references |

## 3. E1 first vertical slice

Required end-to-end path:

Tauri shell → React view → typed Tauri command → application use case → Work Management domain → SQLite repository → application restart → Workspace and Project restored.

Minimum acceptance:
- Native Windows build and launch.
- Initialize Workspace and create Project.
- Close and restart; verify data restored.
- Run schema migration tests from clean and supported prior state.
- Verify cross-Workspace access denied at backend boundary.
- Verify UI has no direct database access.
- Run domain/application/repository tests and dependency checks.
- Run offline with network disabled.

## 4. E0.3.1 review closure

E0.3.1 is ready for owner ratification when:
- ADR-017–020 each has an explicit disposition and unresolved objection list.
- System, application, data, cross-domain, Agent, and module-boundary documents use consistent terminology and ownership.
- Operation, OperationAttempt, OutboxMessage, Task, Workflow Run, Agent Execution, and Audit Event are not conflated.
- Contract versioning and idempotency rules are consistent across ADR and architecture docs.
- Formal requirement IDs and existing requirement traceability remain unchanged and complete.
- Documentation validator and GitHub Actions validation pass.
- No document claims implementation or verification without reproducible evidence.

## 5. Verification evidence template

For every test or acceptance item record:
- Evidence ID and requirement/ADR reference.
- Commit SHA and build/test environment.
- Exact command or reproducible procedure.
- Expected and actual result.
- Logs/artifact location with secrets redacted.
- Reviewer and date.
- Pass/Fail/Blocked status.

## 6. Non-goals

E0.3.1 does not implement the Rust workspace, SQLite schema, Outbox dispatcher, durable workflow engine, provider adapters, sync protocol, or multi-device service. Those are implementation or later design work, not documentation acceptance.
