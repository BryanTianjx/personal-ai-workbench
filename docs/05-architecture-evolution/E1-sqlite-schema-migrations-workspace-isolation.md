# E1 — SQLite Schema, Migrations and Workspace Isolation

**Decision baseline:** ADR-003, ADR-006, ADR-017–020
**Implementation Status:** Not Implemented
**Verification Status:** Not Verified
**Target:** Single local authoritative SQLite database for Alpha 0.1 through V1.0

## 1. Database policy

- One app-owned `app.sqlite`; no database-per-workspace and no required server.
- SQLite is the local source of truth. PostgreSQL remains a future optional server topology, not an E1 dependency.
- Enable foreign keys on every connection; use WAL for desktop concurrency and a bounded busy timeout. Select and test synchronous durability settings explicitly; default E1 to FULL unless measured evidence justifies a documented change.
- Store UTC timestamps as INTEGER Unix epoch milliseconds.
- Use opaque UUIDv7 text IDs generated by the application.
- Workspace scoping is enforced in application services and repository APIs, not by UI filters.
- Every workspace-owned table carries workspace_id and composite unique/FK constraints prevent cross-workspace references.
- A nullable workspace_id means system scope only when the use case explicitly declares it; NULL is never a wildcard permission.

## 2. Migration policy

Maintain `schema_migrations(version INTEGER PRIMARY KEY, name TEXT NOT NULL, checksum TEXT NOT NULL, applied_at INTEGER NOT NULL)`.

- Migration files are immutable after release. A correction creates a new forward migration.
- Apply each migration in a transaction; write the migration ledger row in the same transaction.
- Verify checksum of already-applied migrations at startup. A mismatch is a hard integrity error; do not silently continue.
- Migrations are ordered, forward-only and deterministic. No network calls or user interaction inside a migration.
- Back up the database before destructive/transformative migrations. Restore path must be tested.
- Do not use automatic destructive down-migrations. Rollback means restore a verified backup or ship a compensating forward migration.
- On unsupported newer schema version, open read-only/recovery mode and explain the incompatibility; never attempt downgrade.
- Migration tests cover empty database, previous-version fixture, interrupted transaction, checksum mismatch, and upgrade with representative data.

## 3. E1 initial logical schema (SQL reference)

The following is a design reference. Production migrations must be reviewed against the selected SQLite driver and tested on Windows before implementation is considered complete.

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE workspaces (
    id              TEXT PRIMARY KEY,
    name            TEXT NOT NULL CHECK (length(trim(name)) BETWEEN 1 AND 120),
    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL
);

CREATE TABLE projects (
    id              TEXT PRIMARY KEY,
    workspace_id    TEXT NOT NULL,
    name            TEXT NOT NULL CHECK (length(trim(name)) BETWEEN 1 AND 200),
    description     TEXT,
    status          TEXT NOT NULL CHECK (status IN ('active','paused','completed','archived')),
    created_at      INTEGER NOT NULL,
    updated_at      INTEGER NOT NULL,
    UNIQUE (id, workspace_id),
    FOREIGN KEY (workspace_id) REFERENCES workspaces(id) ON DELETE RESTRICT
);
CREATE INDEX idx_projects_workspace_updated
    ON projects(workspace_id, updated_at DESC);

CREATE TABLE operations (
    id                          TEXT PRIMARY KEY,
    kind                        TEXT NOT NULL,
    owner_domain                TEXT NOT NULL,
    owner_type                  TEXT NOT NULL,
    owner_id                    TEXT NOT NULL,
    workspace_id                TEXT,
    status                      TEXT NOT NULL CHECK (status IN
      ('Pending','Running','AwaitingApproval','RetryScheduled','OutcomeUnknown',
       'Succeeded','Failed','Cancelled')),
    actor_id                    TEXT NOT NULL,
    correlation_id              TEXT NOT NULL,
    causation_id                TEXT,
    idempotency_key             TEXT,
    request_digest              TEXT,
    cancellation_support        TEXT NOT NULL CHECK (cancellation_support IN
      ('supported','unsupported','unknown')),
    cancellation_requested_at   INTEGER,
    created_at                  INTEGER NOT NULL,
    updated_at                  INTEGER NOT NULL,
    started_at                  INTEGER,
    finished_at                 INTEGER,
    next_attempt_at             INTEGER,
    last_error_category         TEXT,
    last_error_code             TEXT,
    resolution_note             TEXT,
    CHECK (request_digest IS NULL OR length(request_digest) = 64),
    FOREIGN KEY (workspace_id) REFERENCES workspaces(id) ON DELETE RESTRICT
);
CREATE INDEX idx_operations_workspace_status_updated
    ON operations(workspace_id, status, updated_at DESC);
CREATE INDEX idx_operations_due
    ON operations(status, next_attempt_at)
    WHERE status = 'RetryScheduled';
CREATE INDEX idx_operations_owner
    ON operations(owner_domain, owner_type, owner_id);

CREATE TABLE operation_attempts (
    id                  TEXT PRIMARY KEY,
    operation_id        TEXT NOT NULL,
    attempt_no          INTEGER NOT NULL CHECK (attempt_no > 0),
    phase               TEXT NOT NULL CHECK (phase IN
      ('prepare','submit','poll','cancel','reconcile')),
    started_at          INTEGER NOT NULL,
    finished_at         INTEGER,
    outcome             TEXT NOT NULL CHECK (outcome IN
      ('started','rejected','accepted','completed','failed','indeterminate','cancelled')),
    request_digest      TEXT,
    idempotency_key     TEXT,
    external_reference  TEXT,
    retryable           INTEGER NOT NULL CHECK (retryable IN (0,1)),
    error_category      TEXT,
    error_code          TEXT,
    evidence_ref        TEXT,
    UNIQUE (operation_id, attempt_no),
    FOREIGN KEY (operation_id) REFERENCES operations(id) ON DELETE RESTRICT
);
CREATE INDEX idx_operation_attempts_operation
    ON operation_attempts(operation_id, attempt_no DESC);

CREATE TABLE outbox_messages (
    id                  TEXT PRIMARY KEY,
    workspace_id        TEXT,
    producer_domain     TEXT NOT NULL,
    aggregate_type      TEXT NOT NULL,
    aggregate_id        TEXT NOT NULL,
    event_type          TEXT NOT NULL,
    schema_version      INTEGER NOT NULL CHECK (schema_version > 0),
    occurred_at         INTEGER NOT NULL,
    correlation_id      TEXT NOT NULL,
    causation_id        TEXT,
    payload_json        TEXT NOT NULL CHECK (json_valid(payload_json)),
    status              TEXT NOT NULL CHECK (status IN
      ('Pending','Leased','Delivered','Quarantined')),
    attempts            INTEGER NOT NULL DEFAULT 0 CHECK (attempts >= 0),
    available_at        INTEGER NOT NULL,
    lease_owner         TEXT,
    lease_until         INTEGER,
    created_at          INTEGER NOT NULL,
    delivered_at        INTEGER,
    last_error_category TEXT,
    FOREIGN KEY (workspace_id) REFERENCES workspaces(id) ON DELETE RESTRICT
);
CREATE INDEX idx_outbox_dispatch
    ON outbox_messages(status, available_at, created_at);
CREATE INDEX idx_outbox_workspace
    ON outbox_messages(workspace_id, created_at DESC);

CREATE TABLE processed_messages (
    consumer_name       TEXT NOT NULL,
    message_id          TEXT NOT NULL,
    processed_at        INTEGER NOT NULL,
    outcome             TEXT NOT NULL CHECK (outcome IN ('Applied','Ignored')),
    handler_version     TEXT,
    PRIMARY KEY (consumer_name, message_id),
    FOREIGN KEY (message_id) REFERENCES outbox_messages(id) ON DELETE RESTRICT
);
```

If SQLite is built without JSON1, replace `json_valid` with application-side strict JSON validation and add an explicit capability test. System-scoped rows with NULL workspace_id must be separately authorized by a system capability; they are not visible to ordinary workspace queries.

## 4. Workspace isolation contract

Every repository method that reads or mutates a workspace-owned row requires an explicit WorkspaceId parameter. Do not expose unscoped `get_by_id(id)` methods for workspace-owned records.

Required rules:
- Resolve active workspace from trusted application context; never trust a workspace ID supplied only by the UI.
- Authorize actor + capability + workspace + resource before each protected side effect.
- Include workspace_id in predicates even when a globally unique ID is supplied.
- For relationships between workspace-owned rows, use composite FK (resource_id, workspace_id) and matching UNIQUE(resource_id, workspace_id) constraints.
- Cross-workspace references are rejected by default. Any future explicit share/transfer workflow requires a separate contract and audit event.
- Search, Dashboard, background workers, imports, notifications, exports and recovery jobs apply the same scope policy.
- System-scope records require explicit system capabilities and are never returned by workspace-scoped list APIs.
- Logs and errors must not leak data from another workspace.

## 5. Backup, restore and integrity

- Use SQLite online backup API or a transactionally safe snapshot; do not copy a live WAL database file alone.
- Verify restored database with integrity_check and foreign_key_check.
- Backup includes schema version, creation timestamp and application version metadata.
- Restore to a temporary path, validate, then atomically replace the active database after closing connections.
- Test backup/restore across at least one schema migration.
- Attachments are stored outside SQLite under workspace-specific directories; database metadata and file access checks must enforce the same WorkspaceId.

## 6. E1 migration sequence

- 0001: workspaces and projects; constraints and indexes; migration ledger.
- 0002: operations, operation_attempts, outbox_messages and processed_messages.
- Later migration: tasks and remaining Alpha domain tables only after their domain contracts are frozen. Do not front-load all eight domains into the first migration.

## 7. Acceptance tests

- Empty database initializes and records checksums.
- Existing fixture upgrades exactly once and preserves data.
- Applied migration checksum mismatch fails closed.
- Foreign keys are enabled on every pooled connection.
- Cross-workspace project lookup/update/delete is denied even with a valid record ID.
- Cross-workspace relationship insert fails at SQLite constraint level.
- Background job and Dashboard query scope tests pass.
- Duplicate Outbox delivery creates one local consumer effect.
- Crash after dispatch but before Delivered causes safe redelivery.
- Backup/restore passes integrity_check and foreign_key_check.
