## 1. Executive result

The four E0.3 ADR proposals are directionally sound and compatible with the existing Modular Monolith, Local-first, SQLite and eight-domain baseline, provided the clarifications in this review are retained. No ninth business domain, microservice, mandatory server, or per-domain crate explosion is introduced.

**Recommended disposition:** Accept ADR-017, ADR-018, ADR-019 and ADR-020 with the recorded clarifications. Their formal status remains Proposed until explicit repository-owner ratification. Implementation and verification remain Not Implemented / Not Verified.

## 3. Consolidated target architecture

- Experience: Tauri 2 + React + TypeScript.
- Application coordination: use cases, authorization orchestration, operation tracking, Outbox and recovery.
- Domain: eight business domains retain ownership and invariants.
- Infrastructure: SQLite, filesystem, OS credential store, Outbox dispatch and adapters.
- External ecosystem: Agent providers, Git, Hindsight, Lingshu and optional remote services.

The Coordination Layer is not a business domain. Operation is not a Task, Workflow Run or Agent Execution. Events are at-least-once and consumers idempotent; remote exactly-once execution is not claimed.

## 4. Key risks resolved by clarification

1. Avoid coordinator god-object: named cross-domain use cases only; domain invariants stay local.
2. Avoid premature crate sprawl: four initial crates, domain modules first.
3. Avoid duplicate lifecycle state: Operation references owning records and records attempts; no shadow business state.
4. Avoid false exactly-once guarantees: Outbox delivery at-least-once; reconcile indeterminate provider outcomes.
5. Avoid accidental authorization inheritance: reauthorize each protected side effect; approval does not expand grants.
6. Avoid over-versioning: version published DTOs and persisted event envelopes, not private methods.

## 6. Open decisions before E1 implementation

- Final physical SQLite schema and migration order for Operation, OperationAttempt, OutboxMessage and ProcessedMessage.
- Retention and privacy policy for operation attempts and diagnostic data.
- Concrete idempotency-key format and request digest canonicalization.
- Outbox dispatcher scheduling, retry budget and quarantine recovery UX.
- Whether architecture checks use cargo metadata/custom script or an established dependency checker.
- Attachment content addressing and SQLite performance prototype remain separate evidence-driven design items.

These do not invalidate the proposed architecture but must be resolved before the corresponding implementation is considered complete.
