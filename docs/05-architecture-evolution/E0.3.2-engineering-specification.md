# E0.3.2 — Engineering Specification: Durable Operations and Messaging

**Decision baseline:** ADR-017–020 Accepted (2026-11-08)
**Implementation Status:** Not Implemented
**Verification Status:** Not Verified
**Scope:** Logical contracts for Operation, OperationAttempt, OutboxMessage and ProcessedMessage

## 1. Normative principles

1. Each business domain remains authoritative for its own records and state machine.
2. Operation is a durable execution envelope. It references an owner record; it does not mirror Task, Workflow Run, Agent Execution, or publication state.
3. OperationAttempt records one actual execution attempt, especially a side-effecting provider call. It is append-oriented; corrections are represented by later records or controlled metadata updates, not history rewriting.
4. OutboxMessage records durable intent to publish a versioned event. It is committed in the same SQLite transaction as the local state transition that requires publication.
5. ProcessedMessage records consumer deduplication. Insert the marker in the same transaction as the consumer's local effect whenever both are in the same database.
6. Delivery is at-least-once. Exactly-once remote side effects are not promised.
7. All times are UTC Unix epoch milliseconds. IDs are opaque UUIDv7 strings generated by the application; consumers must not infer ordering or authorization from an ID.
8. Payloads and diagnostics are minimized. Never persist credentials, access tokens, raw prompts, full documents, or raw attachments in event envelopes or error messages.

## 2. Operation

Logical fields:

| Field | Type | Required | Meaning |
|---|---|---:|---|
| id | UUIDv7 text | yes | Stable operation identifier |
| kind | bounded string | yes | Use-case kind, e.g. project.import or agent.invoke |
| owner_domain | bounded string | yes | Owning domain key |
| owner_type | bounded string | yes | Owning aggregate/record type |
| owner_id | opaque text | yes | Owning record ID; not a foreign key to arbitrary domain tables |
| workspace_id | UUIDv7 text | conditional | Required for workspace-scoped work; null only for explicitly system-scoped operations |
| status | enum text | yes | Operation lifecycle below |
| correlation_id | opaque text | yes | End-to-end diagnostic correlation |
| causation_id | opaque text | no | Command/event/operation that caused this operation |
| actor_id | opaque text | yes | Initiating principal; never an authorization grant |
| idempotency_key | opaque text | no | Scoped command intent key |
| request_digest | SHA-256 hex | no | Digest of canonical, minimized request representation |
| created_at / updated_at | int64 ms | yes | Creation and latest transition time |
| started_at / finished_at | int64 ms | no | Execution timestamps |
| next_attempt_at | int64 ms | no | Earliest eligible retry time |
| cancellation_requested_at | int64 ms | no | Cancellation request timestamp |
| cancellation_support | enum | yes | supported, unsupported, unknown |
| last_error_category | bounded enum | no | Safe category, not raw provider error |
| last_error_code | bounded text | no | Stable internal code |
| resolution_note | bounded text | no | Safe human resolution summary; no secrets |

Operation status values: Pending, Running, AwaitingApproval, RetryScheduled, OutcomeUnknown, Succeeded, Failed, Cancelled. Terminal states are Succeeded, Failed and Cancelled. OutcomeUnknown is non-terminal and blocks non-idempotent retry until reconciliation or explicit human resolution. A cancellation request does not prove remote cancellation.

Allowed high-level transitions:
- Pending → Running | AwaitingApproval | Cancelled | Failed
- AwaitingApproval → Pending | Running | Cancelled | Failed
- Running → RetryScheduled | OutcomeUnknown | Succeeded | Failed | Cancelled
- RetryScheduled → Running | Cancelled | Failed
- OutcomeUnknown → Running (only after reconciliation proves no effect or safe idempotent retry) | Succeeded | Failed | Cancelled
- Terminal states do not transition; corrections require a new operation or explicit administrative repair record.

Every transition is validated in the application service and persisted before progress is shown as durable. A lease/worker claim is an implementation detail and must not replace lifecycle status.

## 3. OperationAttempt

One row per actual attempt; do not create an attempt merely because a retry timer was scheduled.

| Field | Type | Required | Meaning |
|---|---|---:|---|
| id | UUIDv7 text | yes | Attempt ID |
| operation_id | UUIDv7 text | yes | Parent operation |
| attempt_no | positive integer | yes | Monotonic per operation |
| phase | bounded enum | yes | prepare, submit, poll, cancel, reconcile |
| started_at / finished_at | int64 ms | yes/no | Attempt timing |
| outcome | enum | yes | started, rejected, accepted, completed, failed, indeterminate, cancelled |
| request_digest | SHA-256 hex | no | Canonical request digest |
| idempotency_key | opaque text | no | Provider/command idempotency key |
| external_reference | bounded text | no | Provider execution ID; sensitive values excluded |
| retryable | boolean | yes | Classification result |
| error_category / error_code | bounded text | no | Safe normalized diagnostic |
| evidence_ref | opaque text | no | Reference to separately protected evidence, if any |

Unique constraint: (operation_id, attempt_no). A rejected-before-submit attempt may be retried according to policy. An accepted attempt is polled/reconciled, not resubmitted. An indeterminate post-submit attempt moves the Operation to OutcomeUnknown. Reusing an idempotency key with a different canonical request digest is a conflict.

## 4. OutboxMessage

| Field | Type | Required | Meaning |
|---|---|---:|---|
| id | UUIDv7 text | yes | Event ID and deduplication key |
| workspace_id | UUIDv7 text | conditional | Workspace scope; null only for explicitly system-scoped events |
| producer_domain | bounded text | yes | Owning producer |
| aggregate_type / aggregate_id | bounded text | yes | Source aggregate identity |
| event_type | bounded text | yes | Stable event name |
| schema_version | positive integer | yes | Contract version |
| occurred_at | int64 ms | yes | Domain occurrence time |
| correlation_id / causation_id | text | yes/no | Trace context |
| payload_json | JSON text | yes | Minimal versioned payload |
| status | enum | yes | Pending, Leased, Delivered, Quarantined |
| attempts | non-negative integer | yes | Dispatch attempt count |
| available_at | int64 ms | yes | Retry eligibility |
| lease_owner | text | no | Dispatcher identity |
| lease_until | int64 ms | no | Lease expiry |
| created_at / delivered_at | int64 ms | yes/no | Delivery timestamps |
| last_error_category | bounded text | no | Safe diagnostic |

Dispatcher claims a bounded batch in a short transaction, writes lease metadata, commits, then dispatches outside the transaction. A crash after send but before Delivered can cause redelivery; consumers must deduplicate. Retry uses bounded exponential backoff with jitter and a configurable maximum attempt/age budget. Exhaustion moves to Quarantined. Re-drive is an explicit audited action that preserves event ID and records the operator/action; it must not silently create a different event.

## 5. ProcessedMessage

| Field | Type | Required | Meaning |
|---|---|---:|---|
| consumer_name | bounded text | yes | Stable consumer identity |
| message_id | UUIDv7 text | yes | Outbox event ID |
| processed_at | int64 ms | yes | First successful local application |
| outcome | enum | yes | Applied, Ignored |
| handler_version | bounded text | no | Consumer implementation version |

Primary key: (consumer_name, message_id). Unknown event types may be marked Ignored only when no required invariant depends on them. Unsupported schema versions are quarantined/rejected, not guessed. A duplicate message returns the previously committed outcome without reapplying effects.

## 6. Idempotency and canonicalization

- Scope a key by workspace (when applicable), command/consumer identity, and intent; never treat a globally repeated string as globally unique.
- Canonicalize only validated semantic input: stable field ordering, normalized enum representation, explicit null/omission policy, normalized Unicode, and deterministic number representation.
- Exclude volatile transport metadata such as request timestamp, trace IDs, retry count and UI state.
- Hash canonical UTF-8 bytes with SHA-256. Persist the digest beside the key.
- Same scope + same key + same digest returns the prior result/status. Same scope + same key + different digest returns Conflict and is audited.
- If a provider has no idempotency support, reconcile external state before repeating an indeterminate side effect.

## 7. Retention and privacy baseline

- Operation and attempt history is user-visible operational history; do not silently cascade-delete it with an owner record.
- Initial E1 policy: retain successful/failed/cancelled operation metadata for 90 days; retain OutcomeUnknown and Quarantined records until resolved plus 90 days; allow user-initiated export before purge.
- Retention is configurable later; no automatic purge implementation is part of the first vertical slice.
- Keep only normalized error category/code in SQLite. Raw provider diagnostics, if ever required, belong in a separately protected, size-limited and retention-governed diagnostic store.
- Audit security-relevant transitions and manual re-drive/resolution through System & Security.

## 8. Required invariants

- Operation owner reference is immutable after creation.
- workspace_id is immutable after creation.
- Attempt numbers are unique and monotonically allocated transactionally.
- Outbox intent and source local state change commit atomically.
- ProcessedMessage and consumer local effect commit atomically where possible.
- No provider/network call occurs while a SQLite write transaction is open.
- No protected side effect executes without fresh authorization.
- No non-idempotent resubmission while the prior outcome is indeterminate.
