## 1. Executive result

E0.3.2 establishes the approved architecture decision baseline and translates it into an E1 engineering specification. ADR-017 through ADR-020 are Accepted. Their E0.3.1 clarification clauses are normative.

This acceptance is not evidence of implementation. No claim is made that the Rust workspace, SQLite schema, migration runner, dispatcher, or UI vertical slice already exists or has passed runtime tests.

## 4. Key engineering decisions

- Operation owner identity and workspace scope are immutable after creation.
- OperationAttempt is append-oriented and one row represents one actual attempt.
- Outbox intent is committed atomically with source local state; dispatch is outside the transaction and at-least-once.
- ProcessedMessage deduplication is committed atomically with consumer local effects where feasible.
- Same idempotency scope/key with a different canonical request digest is a conflict.
- OutcomeUnknown blocks unsafe non-idempotent resubmission until reconciliation or human resolution.
- One authoritative SQLite database is retained. Workspace isolation is enforced by trusted application context, scoped repository methods and composite database constraints.
- Migrations are forward-only, transactional, checksum-verified and never silently downgraded.
- E1 prioritizes one Windows vertical slice; all eight domains are not implemented in this milestone.

## 5. E1 work packages

E1-01 toolchain and workspace baseline; E1-02 crate boundaries; E1-03 SQLite foundation; E1-04 Workspace isolation; E1-05 Work Management vertical slice; E1-06 restart and backup; E1-07 durable operation foundation; E1-08 Outbox and deduplication; E1-09 security and audit gates; E1-10 release-readiness review.

The first visible user outcome is creating a Project in a Workspace and finding it restored after application restart.

## 6. Acceptance gates

Architecture, persistence, security, reliability, product and evidence gates are defined in the E1 delivery plan. E1 is not complete until the native Windows application builds and launches, data survives restart, cross-Workspace access is denied, migration and backup/restore tests pass, and CI evidence is tied to the exact candidate commit.

## 7. Scope and governance

This report authorizes design and planning only. It does not authorize automatic commit, push, merge, release, deployment, destructive migration, or external provider execution. Integration and repository promotion remain explicit human decisions.
