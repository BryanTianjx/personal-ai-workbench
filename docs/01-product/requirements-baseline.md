# 需求基线与追踪规则

**状态：** Draft baseline；待 E0 评审冻结
**版本：** 0.1.0

## 1. 优先级定义

- **P0：** Alpha 0.1 发布阻断需求。
- **P1：** 重要能力，允许在后续 Alpha/Beta 完成，但必须有明确计划；若为其他能力的安全前置条件，必须在依赖能力启用前完成。
- **P2：** 长期增强，不属于当前发布承诺。

## 4. P2 需求
多设备同步和冲突解决、独立 Web Server、可视化工作流编辑器、多 Agent 团队协作、知识图谱、多平台内容分发、高级个人成长分析。

## 5. Agent 安全前置门禁

PAW-S-004 的目标版本为 Alpha 0.2，不属于 Alpha 0.1 的 Agent 功能交付承诺。Alpha 0.1 必须完成授权模型、接口边界和测试规范的设计；Agent 外部执行保持关闭。Alpha 0.2 中，只有在默认拒绝、最小权限、资源范围校验、人工审批绑定执行计划、审计记录及相应自动化测试均实现并通过验收后，才可启用 Agent 执行。任何未满足条件的适配器只能提供状态/能力展示，不得产生受保护的外部副作用。

## 6. 追踪规则
每条需求应关联 PRD 章节、设计/架构文档、实现模块或任务 ID、自动化测试或人工验收用例、当前状态与证据。状态统一为 proposed、approved、implemented、verified、deferred、rejected。未经测试不得标记 verified。

## 7. 冻结规则
需求冻结后，变更必须记录原因、用户价值、影响模块、数据迁移、安全和平台影响、验收标准及目标版本。P0 变更需要重新评审发布范围。
